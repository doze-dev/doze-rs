# Fix: SQS and DynamoDB gaps against the Go edition (stage note, 2026-11-13)

Branch `aws-fix-sqs-dynamodb`, on `aws` at `0fc1f7b8`. The integrator folds this note into `PLAN.md`, `STATUS.md`, `scoreboard.md` and
`weight.md`; none of those was touched here. The SQS 60-second delete and purge windows are unchanged (the owner decides them separately).

## What was closed

1. **SQS retention expiry when idle** (Go SUPPORT ~2562, 2603). A message past `MessageRetentionPeriod` is gone at once for every reader:
   the counts (`ApproximateNumberOfMessages`, `...NotVisible`, `...Delayed`) are computed against the clock and leave it out, and so does
   `DozePeek`. Physical removal is lazy and deadline-driven, with no periodic tick: every call checks the oldest message of each queue;
   after every call the actor answers when the first message of any queue expires, and one task per region sleeps to that time, sweeps
   every queue thoroughly, and ends when no queue holds a message. A message moved in from another queue keeps its send time, so one
   further back in a queue can be older than the first: it is counted out at once and removed no later than the first message's own
   expiry. The timer is the new `doze_runtime::Deadlines` (below). Tests: `aws-sqs/src/tests/retention.rs` (counts, lazy removal, the
   tick, and the timer running only while a queue holds a message, then stopping with no call).
2. **`DozePeek`** (Go ~2560, `sqs/receive.go` `Peek`, `sqs/actions.go` `hDozePeek`). Exposed as Go exposed it: `X-Amz-Target:
   AmazonSQS.DozePeek` on the SQS endpoint. It is not in the model, so the gateway gained an additive hook: `Service::extension(name)`
   names an operation the service adds and the model operation whose input and output shapes it borrows (`ReceiveMessage` here); the
   call carries an index past the model's (`1 << 16`). Nothing changes for an operation the model has; an unknown name is still 404
   `UnknownOperationException`. What it returns: the messages a receive could be given now (not in flight, not delayed, not expired),
   every FIFO group's and not only each head, oldest first, with the system and message attributes asked for; no receive count, no
   visibility change, no new handle (a message received before carries its latest handle; one never received has none). Bounded:
   `MaxNumberOfMessages` 1 to 100, default 10 (the console asks for 50); outside that it is `InvalidParameterValue`. Authorized as
   `sqs:ReceiveMessage` on the queue. Tests: `retention.rs` (no side effects, every group, the bound) and the gateway test
   `an_operation_the_service_adds_borrows_a_model_operations_shapes`; checked by hand against the release binary.
3. **DynamoDB Streams wire API** (Go ~833, 846; SCOPE "streams through every door"). New crates `aws-dynamodb-streams` (the service) and
   `aws-model-dynamodb-streams` (generated by `cargo xtask codegen` from `models/dynamodb-streams.json`, fetched 2026-11-13 from
   `aws/api-models-aws` at `f231310c`, recorded in `models/PROVENANCE.md`). `ListStreams` (by table, `Limit`, `ExclusiveStartStreamArn`),
   `DescribeStream` (one shard, `ExclusiveStartShardId`, `ShardFilter` `CHILD_SHARDS` answers none), `GetShardIterator` (`TRIM_HORIZON`,
   `LATEST`, `AT_SEQUENCE_NUMBER`, `AFTER_SEQUENCE_NUMBER`, and the model's new `AT_TIMESTAMP`), `GetRecords` (`Limit` up to 1,000,
   `NextShardIterator` while the shard is open, iterators expire after 15 minutes with `ExpiredIteratorException`). It holds no state: it
   reads the records `aws-dynamodb` keeps (`Dynamodb::stream_records`, and a new `Dynamodb::streams` for what streams exist). Routing:
   DynamoDB and DynamoDB Streams both sign as `dynamodb`; the gateway now indexes services by their service shape too and picks the one
   the `X-Amz-Target` prefix names when it signs as the request does, falling back to the signing name as before (additive: every
   other service routes as it did). The streams service is registered on the gateway only, not on the peer bus (which keys services by
   signing name and would shadow DynamoDB). IAM: `dynamodb:ListStreams` on `table/*/stream/*`, the other three on the stream ARN.
   Tests: `aws-dynamodb-streams/src/tests.rs`, and the boto3 scenario `test_streams_api` passes against the release binary.
4. **PartiQL** (Go ~832; SCOPE DEFER "keep single-statement"). `ExecuteStatement` is built in full; `BatchExecuteStatement` and
   `ExecuteTransaction` are built too, because they cost little once a statement translates onto the classic operations, and SCOPE's
   reason for deferring them (Go's `ExecuteTransaction` was not atomic, DDB-33) does not hold here: a transaction is one
   `TransactWriteItems` (or `TransactGetItems` for all-read), all or nothing. A statement is parsed (`aws-dynamodb/src/partiql/parse.rs`,
   bounded: the model's 8,192 characters, nesting cut at 32, `// fuzz:parser fuzz_partiql` with its target in
   `crates/aws-dynamodb/fuzz/`; 584,000 inputs in 60 s on nightly, no finding; a fixed 20,000-mutation run is part of the unit tests)
   and run as the classic operation it means, so it shares storage, key checks, conditions, `aws-expr` expressions, streams and
   refusals: `SELECT` with exactly the whole key by equality is `GetItem`, any other `SELECT` a `Scan` of the table or of
   `"table"."index"` with the `WHERE` as its filter (`Limit`, `NextToken`); `INSERT ... VALUE {...}` a `PutItem` that may not replace
   (`DuplicateItemException`); `UPDATE ... SET/REMOVE ... WHERE` an `UpdateItem` that needs the whole key and the item to exist, the rest
   of the `WHERE` its condition (`SET` takes `+`, `-`, `list_append`, `if_not_exists`, `set_add`, `set_delete`); `DELETE` a `DeleteItem`.
   `WHERE` takes the six comparisons, `AND`, `OR`, `NOT`, parentheses, `BETWEEN`, `IN [...]`, `begins_with`, `contains`,
   `attribute_type`, `size`, `IS [NOT] MISSING`, `IS [NOT] NULL`; values are `?`, strings, numbers, booleans, `NULL`, lists, maps and
   `<<sets>>`; `RETURNING ALL|MODIFIED OLD|NEW *`. Refused by name (501 `NotImplemented`, "PartiQL X is not built in doze-aws."):
   `ORDER BY`, `EXISTS`, functions in a select list, `UPSERT`/`REPLACE`, `MISSING` as a value, `set_add`/`set_delete` on another
   attribute. A batch of two writes to one item is refused whole ("Provided list of item keys contains duplicates"): each statement
   reads the table as it was before the batch. IAM: `dynamodb:PartiQLSelect`/`Insert`/`Update`/`Delete` on the table (or index).
   Tests: `aws-dynamodb/src/tests/partiql.rs`, the parser's own tests, and two boto3 scenarios.
5. **TTL by deadline** (Go ~821). The sweep still runs at the start of every call; now it also runs when due with no call: after every
   call that wrote (and at open) the actor reads the first entry of each TTL-enabled table's time-to-live index, and one task per region
   sleeps to the earliest expiry, sweeps, and ends when no item has a time to live. `Dynamodb::resume` (called once at start in
   `run.rs`, as CloudWatch's and EventBridge's are) arms the regions that have DynamoDB state on disk. A deletion is a REMOVE stream
   record with `userIdentity` `{"type":"Service","principalId":"dynamodb.amazonaws.com"}` (Lambda's casing; `GetRecords` writes the
   model's `Type`/`PrincipalId`), and the deletion now wakes a waiting Lambda consumer (before, a sweep at the start of a call dropped
   its own `appended` flag). AWS deletes within days; here an item goes at its expiry second. Tests: `aws-dynamodb/src/tests/expiry.rs`
   (the deadline, a tick, and an item expiring with no call and its REMOVE record).
6. **Contributor Insights** (Go ~831 tier C; SCOPE ~199 accept-and-flag). `UpdateContributorInsights`, `DescribeContributorInsights`,
   `ListContributorInsights`, per table and per index, stored in a new `insights` table of the region's redb file (created in a file
   made before it), removed with the table. An update answers `ENABLING`/`DISABLING` and the next describe says `ENABLED`/`DISABLED`
   (what Terraform waits for); the mode defaults to `ACCESSED_AND_THROTTLED_KEYS`; nothing is computed, so no rule list is returned.
   Tests: `expiry.rs`, and a boto3 scenario.

## Shared code changed (outside the three crates)

- `doze-runtime`: new `Deadlines<S>` (`src/deadlines.rs`): one task per key asleep until a `Lazy` service's next deadline, none while
  nothing is due; CloudWatch's alarm-timer pattern made generic (CloudWatch itself is not changed). Its `tokio` gains the `macros`
  feature (already on through other crates in every binary, so no build change).
- `aws-wire`: `Service::extension` and the `Extension` type (default none).
- `aws-gateway`: services indexed by service shape for the target-prefix choice; the extension hook in the JSON path; a gateway test.
- `doze-aws`: `run.rs` passes `dynamodb.clone()` into the list, registers the streams service on the gateway, and calls
  `dynamodb.resume()`; `Cargo.toml` gains `aws-dynamodb-streams`.
- `models/dynamodb-streams.json`, `models/PROVENANCE.md`, the generated `crates/aws-model-dynamodb-streams`.
- `conformance/tests/test_dynamodb.py`: four scenarios (PartiQL statements; PartiQL batch and transaction; Contributor Insights; the
  Streams API), UNVERIFIED until recorded. No SQS scenario: retention needs at least 60 seconds and AWS's timing is approximate, and
  `DozePeek` is not an AWS operation.

## `(memory)`: wording and formats not checked against a recording

- SQS `DozePeek`: the bound and its message are doze's (the operation is). The counts leaving expired messages out is behaviour, not
  wording; AWS deletes "at some point" after the retention.
- PartiQL: every message (`Statement wasn't well formed, can't be processed: ...`, `Number of parameters in request and statement don't
  match.`, `Where clause does not contain a mandatory equality on all key attributes`, `Duplicate primary key exists in table`, the
  all-reads-or-all-writes and whole-key messages, `Invalid NextToken`, `Provided list of item keys contains duplicates`); that a write
  answers `Items: []`; that an `UPDATE` of a missing item is `ConditionalCheckFailedException`; the `DuplicateItem` cancellation reason;
  the batch error codes; `ExecuteTransaction` answering `{}` for writes; a scan answering both `NextToken` and `LastEvaluatedKey`;
  `IS NULL` being true for a missing attribute.
- Contributor Insights: the `ENABLING`/`DISABLING` answer, the default mode, the absent rule list, the missing-index message.
- Streams: the shard id (`shardId-` + 20 digits + `-` + 8 hex; here the stream's creation time and its id), sequence numbers as the 21
  digits the stream records already carry, `StartingSequenceNumber` `...001`, the iterator's form, every error message, `ListStreams` of
  an unknown table answering an empty list, the 1,000-record `Limit` refusal. `TrimmedDataAccessException` is never raised (a trimmed
  record is simply not there). A disabled stream is not listed: `UpdateTable` still drops it (AWS keeps it readable for 24 hours).
- TTL: deletion at the expiry second (AWS: within days).

## Not done / open

- No SQS `resume`: after a restart an expired message is counted out by the clock at once, and removed at the first call (which arms
  the timer); opening SQS at boot only to arm it was not worth the idle cost.
- The four boto3 scenarios await a recording.
