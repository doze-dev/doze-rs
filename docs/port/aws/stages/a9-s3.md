# A9: S3 (branch `aws-a9-s3`, 2026-11-12)

Status: built to the three milestones of the brief (codec and basics; listing, versioning, multipart and checksums; configuration,
presigned URLs, notifications and lifecycle). Not merged, not pushed. The numbers below are the ones I measured; an independent
review is expected to re-run them.

## What was built

**The restXml codec (`crates/aws-wire/src/rest*`, shared).** The model's `@http` bindings are the routing table: `rest::route` builds,
on first use, a router from method, path template (`/{Bucket}/{Key+}`), literal query parameters (`?uploads`, `?list-type=2`) and the
input members that are required and travel in the query or a header (`uploadId`, `x-amz-copy-source`); of the routes a request fits
the one naming the most literals wins, which is how `PutObject` is told from `CopyObject` and `GetObject` from `ListParts`.
`rest::request` reads path labels, query, headers, header prefixes (`x-amz-meta-*`) and an XML or plain payload into the JSON the
normal validating decoder takes (so a REST request is held to the same rules as a JSON one). `rest::xmlin` is a small hand-written XML
reader (no DTD, depth and element caps; fuzz target `fuzz_xml` with seeds, compile-checked only, not run: no nightly here).
`rest::response` writes headers, header prefixes, status members, payload (raw or XML) and the XML body under the output structure's
own root element; errors are S3's `<Error>` document with the extra fields (`BucketName`, `Key`, ...), empty for HEAD.
`Service::rest()` (default `None`) and the `RestService`, `Upload` and `ByteStream` traits carry the streams.

**The gateway branch (`crates/aws-gateway/src/rest.rs`, `upload.rs`, `body.rs`, `presign.rs`, small edits to `pipeline.rs`).**
Path-style and virtual-host addressing (`bucket.s3.<anything>[:port]`, any `s3` or `s3-region` label after at least one other label;
IP addresses are path style); `Expect: 100-continue` (hyper answers it when the body is first read; the 100 arrives for an accepted upload, tested over a socket,
and a request the gate refuses first (no such bucket) was seen to get its final answer without one); uploads reach the service as a pulled stream, plain or
aws-chunked with the chunk signatures (or the unsigned trailing checksum) checked as the chunks arrive; downloads leave as a stream.
Neither is ever held whole. Presigned URLs: SigV4 query URLs go through `aws-auth`; **boto3's default S3 presigned URL is SigV2**,
which AWS accepts (recorded), so a trusting gateway takes its access key as given and holds it to its `Expires`, and checks that
every header a SigV4 presigned URL signed is on the request (without that check a presigned PUT that AWS refuses would be accepted);
a verifying gateway still refuses SigV2 (open item below). An unsigned request to a trusting gateway is served as the local account
(curl, a browser).

**`crates/aws-s3`.** Sans-IO `Core` behind a regional actor (`doze_runtime::Keyed<Core>`, home region `us-east-1`, other regions in
`regions/<region>`; **buckets are kept apart per region like every other service, so the same bucket name can exist in two regions,
which AWS's global namespace forbids**; PLAN/SCOPE have no decision on this, it is an open decision below). Metadata in one redb file:
buckets, uploads and parts as `Records` in memory; **object versions on disk and read by range scan** (a new `doze_store::Db::scan`
and `Changes::of_rows`), keyed `bucket NUL key NUL (u64::MAX - seq)` so a key's versions are together, newest first. Blobs are files
(`doze-fs`): written to `blobs/<run>.<n>.part`, flushed, renamed, the directory flushed; a multipart object is the list of its parts'
blobs (completing copies no byte). A `running` marker tells a restart the last run did not close, and then blobs nothing refers to are
swept; staging files of other runs are swept always. Crash tests on `SimFs` (`blob.rs`): a published blob survives a power cut, a
half-written one does not, a failed rename leaves nothing.

Built (80 of the model's 112 operations): CreateBucket, DeleteBucket, HeadBucket, ListBuckets, GetBucketLocation; PutObject (with
`If-None-Match`/`If-Match`), GetObject and HeadObject (ranges, `partNumber`, the four conditional headers, `response-*` overrides,
`ChecksumMode`, version ids), DeleteObject, DeleteObjects, CopyObject (metadata and tagging directives, conditional copy-source
headers, versions), ListObjects, ListObjectsV2, ListObjectVersions (prefix, delimiter, paging, `encoding-type=url`),
GetObjectAttributes, object and bucket tagging (Get/Put/Delete), Get/PutBucketVersioning; the whole multipart family
(CreateMultipartUpload, UploadPart, UploadPartCopy, CompleteMultipartUpload with composite and full-object checksums,
AbortMultipartUpload, ListParts, ListMultipartUploads); thirteen bucket configurations stored as sent and returned as sent after AWS's
checks (CORS, policy, lifecycle, encryption, website, logging, notification, ownership controls, public access block, accelerate,
request payment, replication, Object Lock configuration); the 16 id-keyed operations for analytics, inventory, metrics and
intelligent-tiering configurations. Checksums: CRC32, CRC32C, CRC64NVME (default when none is named: AWS computed it for the multipart
object in the recording), SHA1, SHA256, MD5, computed as the bytes pass, held against `Content-MD5`, `x-amz-checksum-*` headers and
trailers and `x-amz-content-sha256`; whole-object checksums of multipart uploads by CRC combination (the recorded
`om/L0dM0gF4=` is reproduced from the parts' CRCs, a unit test). SSE headers are accepted and returned; the bucket default
encryption applies; no KMS call is made (SCOPE does not ask for one).

**Refused by name (32):** all four ACL operations, RestoreObject, SelectObjectContent, GetObjectTorrent, CreateSession,
ListDirectoryBuckets, the bucket-metadata operations, annotations, RenameObject, UpdateObjectEncryption, WriteGetObjectResponse,
GetBucketPolicyStatus, ABAC, legal hold, retention and the other object-lock object operations. 501 `NotImplemented`,
`X-Doze-Not-Built: 1`, before the body is read. An object stored in `GLACIER` or `DEEP_ARCHIVE` is accepted and flagged and its
read answers `InvalidObjectState` (403).

**Authorization (`authz.rs`).** Actions use S3's names where they differ (`ListBucket`, `ListAllMyBuckets`, `GetObjectVersion`,
`PutBucketCORS`, `PutLifecycleConfiguration`, `ListMultipartUploadParts`, ...), bucket and object ARNs, the bucket policy as
`Need.policy` (the resource layer), `s3:prefix` for listings, two needs for CopyObject. The authorizer's `AccessDeniedException` is
worded `AccessDenied`. Checked by hand under `--iam enforce` with an IAM user (denied, allowed by a user policy, allowed by a bucket
policy); not an automated test.

**Notifications (`events.rs`, `notify.rs`).** Configurations are checked when put (events start with `s3:`; a FIFO queue is refused
in the recorded words; a queue that does not exist is refused; entries get an id). Events are noted by the call and delivered once
its changes are on disk, to SQS over the peer bus (`GetQueueUrl`, `SendMessage`): the `s3:TestEvent` when the configuration is put,
ObjectCreated Put/Copy/CompleteMultipartUpload, ObjectRemoved Delete/DeleteMarkerCreated (DeleteObjects raises one per key),
ObjectTagging Put/Delete, LifecycleExpiration, matched against the event patterns and the prefix/suffix filter. **Hooks, not
built:** topics (A8), Lambda functions (A13) and EventBridge (A12) are stored and returned as sent and marked in `deliver_event`.

**Lifecycle (`lifecycle.rs`, `lifecycle_check.rs`, `janitor.rs`).** The rule check on put; enforcement of expiration (days, date),
noncurrent versions (days, newer-versions kept), expired delete markers and stale multipart uploads. A rule selects by prefix, tag and
size alone or under `And`, and only what it selects (a unit test per filter; Go widened these to the whole bucket). Days count to the
next UTC midnight. Armed only when a rule exists: no task and no timer until then; putting a rule arms it and leaves
`lifecycle.armed` in the region's directory so a restart arms without opening any database; it sleeps to the next UTC midnight,
asks each armed region to sweep, and stops when none has a rule. `S3::sweep_now(region)` is the run-now hook. Transitions are
accepted and not acted on.

2. and 3. `test_presigned_urls::put` and `what-the-put-wrote` (trusting gateway only): boto3's presigned PUT is SigV2 and AWS
   refused it (403: the signature covers a Content-Type the client then did not send), which needs the secret to know. In verify mode
   these two match (SigV2 is refused there) and `get` and `get-absent` differ instead (3 again). Implementing SigV2 verification
   would make verify mode 86 of 87.

What the recording taught (all built that way): uploads by boto3 carry a CRC32 that is stored and returned with
`ChecksumType: FULL_OBJECT`; objects are `ServerSideEncryption: AES256` by default and the default bucket encryption document is
`AES256` with `BucketKeyEnabled: false` and `BlockedEncryptionTypes: SSE-C`; `ChecksumMode` decides whether a read returns the
checksum (HEAD by boto3 does not ask); a ranged read is 206 with `Content-Range` even when it covers the whole object, and returns
the checksum only then; `PutBucketPolicy` and `PutBucketTagging` answer 204; the multipart object has the default CRC64NVME even though
the parts carried CRC32; a listing's `NextUploadIdMarker` is present when not truncated; `NextPartNumberMarker` too; a new bucket's
public access block is all true; the lifecycle document carries `TransitionDefaultMinimumObjectSize`; HEAD errors have no body;
`create_bucket` again in `us-east-1` is 200. **Scenario/snapshot change:** `NextUploadIdMarker` is as opaque as `UploadId` (the first
recording kept AWS's raw id, which no run can equal); the scenario now names it opaque and the snapshot value was rewritten offline
to `<NextUploadIdMarker:1>` (the same precedent as KMS's key material id).

## Open decisions for the owner

1. **Regions.** Buckets are per region here (as SQS, SSM, KMS, Secrets). AWS's bucket namespace is global and a request in another
   region gets a 301. Keeping them per region means the same name can exist twice. A global namespace is a change in `Keyed` use.
2. **SigV2 presigned URLs**: accepted by a trusting gateway (the recording requires it), refused by a verifying one. Verifying them is
   about 60 lines in `aws-auth` (HMAC-SHA1 over the V2 string to sign); it would fix `get`/`get-absent` in verify mode.
3. **Unsigned requests are served as the local account** by a trusting gateway (curl works). Under `--iam enforce` the principal
   `anonymous` is not an IAM-issued key and so is treated as the account root; a public-read bucket policy is therefore not needed to
   read, and "anonymous is denied" cannot be tested. Say if anonymous should be a real principal for IAM.
4. Event delivery to topics, Lambda and EventBridge: hooks in `events.rs::deliver_event` (A8, A13, A12).
5. `Location` of CompleteMultipartUpload: path-style local URL (cannot match the recording).
6. Not built and not asked for by SCOPE: object lock and legal hold enforcement, replication, website serving, ACLs, requester pays.
