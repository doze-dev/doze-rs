# EventBridge Scheduler (stream `scheduler`, 2026-11-14)

PLAN decision D2 planned Scheduler as a service of its own; the Go edition had none, so everything here is **beyond Go**. The service
is `crates/aws-scheduler` (signing name `scheduler`, restJson1, `com.amazonaws.scheduler`), served by `doze-aws` and reachable by other
services on the peer bus as `scheduler`. All 12 operations of the model are built.

## What came with it

- **Model.** `models/scheduler.json` from `aws/api-models-aws` at `46135f84` (path, commit and sha256 in `models/PROVENANCE.md`). It is
  an older-style model: members target prelude shapes (`smithy.api#String`) and enums use the Smithy 1.0 `@enum` trait. Codegen now
  reads both (`codegen/src/legacy.rs`, the same rewrite Smithy's own 2.0 upgrade makes); every other generated crate is byte-identical.
- **Expressions and time zones** in `aws-cron`: `at(yyyy-mm-ddThh:mm:ss)` (read by `parse_scheduler` only; EventBridge rules still
  refuse it), and every expression evaluated in an IANA zone (`Schedule::next_in`, `Zone`).
- **CloudFormation**: `AWS::Scheduler::Schedule` and `AWS::Scheduler::ScheduleGroup` (`res/scheduler.rs`; the `Scheduler` family is
  now served). `Ref` is the name; `GetAtt Arn`, and a group's `State`, `CreationDate`, `LastModificationDate`. `StartDate`/`EndDate`
  are taken as ISO 8601 text, as templates give them. Create-only: `Name` (and a schedule's `GroupName`).
- **Parity probe**: one row in `tools/aws-parity/parity.ts` — `model 12 | Go F/C 0 | Rust built 12 | beyond Go: 12`.

## Time zones: the decision, with numbers

Measured 2026-11-14 on a minimal binary built like `release-aws` (opt-level z, fat LTO, stripped), darwin/arm64:

| option | added bytes |
|---|---|
| `chrono` + `chrono-tz` | +1,205,824 |
| `jiff` with the bundled tzdb | +397,200 |
| OS zoneinfo files read at run time | ~0, but differs by machine and **absent on Windows** |
| **chosen: POSIX-rule table** | ~19 KB of source, 597 zones, 93 distinct rules |

A schedule only ever asks about the future, and a zone's future is its current POSIX TZ rule (the footer of its TZif file). So
`crates/aws-cron/src/zones.rs` maps every IANA name to its rule, generated by `bun tools/gen-tz-rules.ts` from the system tzdata
(2026c), and `tz.rs` evaluates the rules (`Mm.w.d`, `Jn`, `n`, quoted names, negative and >24h times, negative DST as in
`Europe/Dublin`, 30-minute DST as in `Australia/Lord_Howe`). Same answers on macOS, Linux and Windows, no dependency. The cost: a
change a government announces is right only after the table is regenerated (re-run the script; the header names the tzdata version),
and an instant before a zone's last historical change is placed by today's rule (only a `StartDate` years in the past could notice).

## Behaviour, call by call

| behaviour | call |
|---|---|
| `rate()`, `cron()`, `at()` syntax | AWS-correct (documented); `at()` takes real calendar dates only |
| cron in a zone: a time the clock skips (spring forward) does not fire that day | AWS-correct (documented example, `cron(30 2 * * ? *)` in Los Angeles) |
| cron in a zone: a time shown twice (fall back) fires once, **at the second showing** | AWS-correct (documented) |
| `rate(1 days)` is 24 h of real time across a DST change | AWS-correct (documented) |
| `at()` in a gap moves on by the gap; in a fold it is the second showing | choice (AWS undocumented; consistent with cron) |
| rate with no `StartDate` fires at once, then every period | AWS-correct (documented: "starts invoking the target immediately") |
| recurring schedules fire at/after `StartDate` and before `EndDate`; `at()` ignores both | AWS-correct (documented) |
| `EndDate` in the past, `StartDate` after `EndDate` refused | AWS behaviour, wording (memory) |
| `ActionAfterCompletion: DELETE` deletes a schedule when it has no next fire (one-time after its fire; recurring past `EndDate`) | AWS-correct (documented) |
| `UpdateSchedule` resets omitted members to defaults | AWS-correct (documented) |
| `GetSchedule` answers `ScheduleExpressionTimezone: UTC`, `ActionAfterCompletion: NONE` and the default `RetryPolicy` (86,400 s, 185) when not given | (memory) — to confirm when recorded |
| `default` group exists in every account, cannot be deleted | AWS-correct; refusal wording (memory) |
| deleting a group deletes its schedules | AWS-correct (documented); **Local: immediate** where AWS shows `DELETING` for a while |
| tags on groups only; a schedule ARN is refused with `ValidationException` | (memory) |
| `ListSchedules` filters `ScheduleGroup`, `NamePrefix`, `State`; both lists page with `MaxResults`/`NextToken` | AWS-correct shape; token is ours (opaque) |
| **Flexible time windows fire at the start of the window** | Local choice: AWS picks any point in the window; every point is a valid outcome, and the start is the one a developer can predict and a test can wait for. Documented in `plan.rs`. |
| Delivery is made **as the execution role**: `AssumeRole` over the bus, the target service asks IAM about the role's session; under `enforce` a role IAM lacks, or one not trusting `scheduler.amazonaws.com`, fails the invocation (dead-lettered); under `soft` it is logged and made as Scheduler | AWS-correct in effect; refusal wording (memory). Better than EventBridge targets here, which deliver as the role unchecked. |
| `CreateSchedule`/`UpdateSchedule` ask `iam:PassRole` on the target's role (with `scheduler:*` on the schedule ARN) | AWS-correct (documented requirement) |
| Templated targets: SQS `SendMessage` (+ `MessageGroupId`, dedup id = execution id (memory)), SNS `Publish`, Lambda `Invoke` (async), EventBridge `PutEvents` (`Source`/`DetailType` from `EventBridgeParameters`), Step Functions `StartExecution`, Kinesis `PutRecord` (`PartitionKey`) | AWS-correct operation per documented template; with no `Input`, `{}` is sent (memory) |
| Universal targets `arn:aws:scheduler:::aws-sdk:<service>:<action>` for the 17 services doze-aws runs (sqs, sns, lambda, sfn, eventbridge, dynamodb, s3, kinesis, ssm, secretsmanager, kms, iam, sts, cloudwatch, cloudwatchlogs, cloudformation, scheduler) | AWS-correct; read-only action prefixes (`get`, `list`, `describe`, ... the documented list) refused at create (wording memory) |
| A target on a service doze-aws does not run (ECS, CodeBuild, Firehose, ...) is accepted, logged at create, and its invocations log "not delivered" | Local: AWS would deliver; not dead-lettered, because that would invent an AWS failure |
| Context attributes `<aws.scheduler.schedule-arn>`, `scheduled-time`, `execution-id`, `attempt-number` in `Input` | AWS-correct (documented) |
| `RetryPolicy` (`MaximumRetryAttempts` default 185, `MaximumEventAgeInSeconds` default 86,400); only retryable failures (5xx, throttling) retry; backoff doubles 1 s → 64 s | AWS-correct policy; backoff curve ours (AWS: "backs off") |
| Dead-letter message: body = the input; attributes `ERROR_CODE` (the target's client-visible code: SQS's `AWS.SimpleQueueService.NonExistentQueue`, as AWS's example shows), `ERROR_MESSAGE`, `EXECUTION_ID`, `EXHAUSTED_RETRY_CONDITION` (retryable failures only), `IS_PAYLOAD_TRUNCATED`, `RETRY_ATTEMPTS`, `SCHEDULED_TIME`, `SCHEDULE_ARN`, `TARGET_ARN`; sent as the role | AWS-correct (documented example) |
| **Deadline-driven timer**: each schedule's next fire is on its record; one `doze_runtime::Deadlines` task per region sleeps to the earliest, re-armed after every call; none while nothing is scheduled; `resume()` at startup | the rule (zero idle wake-ups) |
| After a restart: a one-time schedule that came due while down fires once; recurring ones do not replay missed fires | AWS does not miss fires; we never replay recurring (as EventBridge rules here) and never lose a one-time fire |
| Retries wait in a task and a restart loses them | as EventBridge (SCOPE.md: the 24 h retry is not needed) |
| **Local hook** `POST /_doze/scheduler/<region>/<group>/<name>/fire[?account=]` invokes now and answers `{ScheduleArn, ExecutionId, ScheduledTime, TargetArn, Outcome: DELIVERED/FAILED/NOT_DELIVERED, Error}`; a failure continues into retry/DLQ; a one-time schedule's hook fire is its one fire (completes, deletes if asked); a recurring schedule keeps its plan | doze-only convenience, documented here and in `hook.rs` |
| `ClientToken` idempotency | not acted on (accepted, ignored) |
| `KmsKeyArn` | stored and returned, not used |
