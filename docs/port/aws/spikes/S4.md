# S4: does `jlens-core` evaluate what Step Functions evaluates?

Status: **prediction written 2026-11-12, before recording or measuring.**

## Hypothesis (from `phase0.md`)

`jlens-core =0.31.0` passes a corpus of JSONata cases whose expected answers are recorded from Step Functions `TestState`
(real AWS, `QueryLanguage: JSONata`). Fallback: `seuil`, or an own subset evaluator (S to M).

## Method

- A corpus of single-state Pass definitions (`Output: "{% expr %}"`, some with `Assign`), each with an input document, run through
  `states:TestState` on the recorder account. The recorded `status`, `output`, `error` and `cause` are the oracle. Corpus and results:
  `S4-corpus.json` here; generator `tools/aws-rec/asl-corpus.ts`. TestState is free.
- A Rust harness (scratchpad, not in the repo) binds `$states.input` and the assigned variables, evaluates the expression with
  `jlens-core`, and compares the JSON result with the recorded output (numbers compared as numbers; object key order ignored,
  as JSON equality).
- Groups: arithmetic and comparison, strings, numbers, arrays and higher-order functions, objects, paths and predicates, regular
  expressions, dates, booleans and conditionals, the extra functions AWS adds (`$partition`, `$range`, `$hash`, `$parse`,
  `$base64encode`...), and errors (type errors, division by zero, undefined results).

## Predictions (written before measuring)

1. On the **core JSONata language** (everything except the AWS extras and the error group), `jlens-core` agrees with AWS on at
   least **95%** of cases. The upstream test suite says 1,685 of 1,689, so the misses should be the places AWS's engine (a JVM
   JSONata port) differs from the reference JavaScript one: number formatting, `$string` of large numbers, date formats.
2. **All** AWS extras (`$partition`, `$range`, `$hash`, `$parse`, `$random`, `$uuid`) are absent from `jlens-core`; the host
   registers them (a handful of functions, each under 40 lines). That is expected, not a failure of the hypothesis.
3. **Errors:** the evaluator reports an error for every case where AWS reports `States.QueryEvaluationError`, but the message
   text differs. Matching is by error code only, wording tracked apart (as with the AWS error messages elsewhere).
4. If the core pass rate is under 90%, the hypothesis is false and the fallback is the own subset evaluator.

---

## Result (2026-11-12)

**Verdict: holds.** `jlens-core =0.31.0` is the JSONata engine for `aws-asl`; the S4 fallback (`seuil` or an own evaluator) is not needed.
Corpus: 216 single-state cases recorded from `states:TestState` on the recorder account (181 SUCCEEDED, 31 FAILED with
`States.QueryEvaluationError`, 4 REFUSED as `InvalidDefinition`), in `S4-corpus.json`; generator `tools/aws-rec/asl-corpus.ts`.
The harness is in the scratchpad (`s4/`): it compiles each expression, binds `$states.input`, evaluates, and compares with AWS
(numbers as numbers, object key order ignored; for FAILED and REFUSED cases it counts agreement when jlens also errors, compared by
class only, not by message).

| Group | Cases | Agree | | Group | Cases | Agree |
|---|---|---|---|---|---|---|
| arithmetic | 12 | 11 | | object | 18 | 17 |
| compare | 12 | 12 | | path | 22 | 22 |
| string | 31 | 30 | | conditional | 19 | 17 |
| number | 26 | 26 | | regex | 9 | 8 |
| array | 24 | 24 | | date | 9 | 9 |
| assign | 3 | 3 | | **core total** | **185** | **179 (96.8%)** |
| AWS extras | 12 | 3 bare, 5 with host functions | | errors | 19 | 18 bare, 19 with `$eval` shadowed |

**Against the predictions**

1. Core at least 95%: **met, 96.8%**. The six misses are exactly where AWS's engine (a JVM port) differs from the reference
   JavaScript one, as predicted, but not in the places I named: not number formatting and not dates (all 9 date cases agree).
2. AWS extras absent from `jlens-core`: **true** for `$partition`, `$range`, `$hash`, `$parse` (they answer `T1006`, not a function).
   `$random` and `$uuid` are not in the corpus (non-deterministic) and so untested. Unpredicted: **`$states.context` is the host's
   to bind** (the harness bound `null`; two cases miss for that reason only).
3. Errors by class: **met**: every error and refusal case errors in jlens too, except one, below.
4. The 90% fallback trigger was not reached.

**Two findings that change the plan**

- **`$eval` runs in jlens and is blocked in AWS** (`$eval("1+1")` answers `2` in jlens; AWS fails the state). A host function named
  `eval` shadows the built-in and restores AWS's behaviour (tested: the error group goes to 19 of 19). `aws-asl` must shadow it
  before the first state runs; an expression language that evaluates strings is not something to leave on by accident. Add a test
  that fails if `$eval` ever answers.
- **Host functions can add and shadow functions.** `Bindings::function` took `partition` and `range` in about 20 lines each and
  they agree with AWS on the corpus. So the AWS extras are host code: `$partition`, `$range` (done in the spike), `$hash` (MD5,
  SHA-1/256/384/512; RustCrypto is already in the plan), `$parse`, `$random`, `$uuid`. No fork of `jlens-core` needed.

**Differences from AWS to carry into the behaviour catalogue** (each is a one-line shadow, a pre-compile check, or a documented
difference; the corpus ids are given):

| Case | AWS | jlens-core | Treatment |
|---|---|---|---|
| `5 / 0` (arith-11) | the string `"Infinity"` | error `D1001` | shadow the divide result in a host check, or document |
| `$encodeUrlComponent("a b&c")` (string-25) | `a+b%26c` (form encoding) | `a%20b%26c` | shadow `$encodeUrlComponent` |
| `$type(undefined)` (object-15) | `"undefined"` | undefined | shadow `$type` (also needs a function case) |
| `x ?: y`, `x ?? y` (cond-18, 19) | definition refused | accepted (JSONata 2.x operators) | pre-compile walk of the AST rejects both |
| `$match("aBc", /b/i)` (regex-7) | no match (flag ignored) | match | document; low risk |
| `$partition([], 3)` (aws-10) | fails the state | `[]` | the host function follows AWS |
| `xs[1..2]` inside a predicate (array-19) | definition refused | refused | agrees; recorded as AWS behaviour |

Also recorded, for the interpreter: variables set by `Assign` are **not visible to `Output` of the same state** (AWS answers
undefined, assign-1 to 3); `$states.context` without a mock is not available to `TestState`; `$range` needs all three arguments;
`$max([])` and `$substring(5, 1)` return nothing, which AWS turns into `States.QueryEvaluationError`.

**Cost:** no AWS spend (TestState is free), 216 calls in under two minutes. Size and speed of `jlens-core` in the binary are not
measured here; that belongs to A14's weight line, since the S1b whole-binary budget counts it.
