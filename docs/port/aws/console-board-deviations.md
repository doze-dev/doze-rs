# Where the console does not do what a board says

The boards of the design canvas (`8fb38ec7-de4e-4570-b8c8-d1eabfe70929`) are the spec for the doze-aws console, with one exception:
a board that says something false of doze-aws, or asks for something doze-aws cannot do, is built to what the backend does. Each
such case is a row here, written by the slice that met it. The canvas is not edited.

A row says which board, what the board says, what the backend does (with the file that shows it), and what was decided.
| Board | What the board says | What the backend does | Decision |

The e2e purges twice and sees `PurgeQueueInProgress`. |

## The recorder's result summaries (aws-ui-recorder)

A call record keeps no request or answer body, so a result summary is the few words the gateway reads from the decoded input and
answer as the call goes by (a count, a size, a name), kept as a kind and two numbers (8 bytes in the slot, text only for the
operations whose summary names something) and worded when the console asks. The table is `crates/aws-peers/src/summary/table.rs`: an
operation not in it has no summary, and a call that failed has none. Calls between services (the bus) carry no summary, since the bus
hands back no answer to read; they are named by what they acted on, which now includes an S3 object (`bucket/key`).

| Board | What the board says | What the record can know | Decision |
| --- | --- | --- | --- |
| `s3__bucket-objects`, `s3__bucket-objects-versions`, `s3__object-detail`, `s3__upload-status` (Recent calls) | `200 6 keys`, `200 212 KB`; the three PutObject calls just made; PutObject, GetObject and HeadObject of this key. | A listing's answer holds the keys, an object's size is in its answer (`ContentLength`) or input.
