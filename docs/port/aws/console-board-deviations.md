# Where the console does not do what a board says

The boards of the design canvas (`8fb38ec7-de4e-4570-b8c8-d1eabfe70929`) are the spec for the doze-aws console, with one exception:
a board that says something false of doze-aws, or asks for something doze-aws cannot do, is built to what the backend does. Each
such case is a row here, written by the slice that met it. The canvas is not edited.

A row says which board, what the board says, what the backend does (with the file that shows it), and what was decided.

| Board | What the board says | What the backend does | Decision |
| --- | --- | --- | --- |
| `sqs__queue-delete`, `sqs__queue-deleted`, `sqs__queue-purge`, `sqs__queue-purged` | A delete and a purge are at once, and `--sqs-strict` is the flag that makes doze-aws refuse a re-create or a second purge for 60 seconds. | The wait is the default, as on AWS: `QueueDeletedRecently` and `PurgeQueueInProgress` are answered unless doze-aws starts with `--sqs-skip-60s-waits`; there is no `--sqs-strict` (`crates/aws-sqs/src/queues.rs`, `crates/doze-aws/src/keys.rs`). | The copy says what happens: AWS and doze-aws refuse for 60 seconds, and `--sqs-skip-60s-waits` lifts it. The e2e purges twice and sees `PurgeQueueInProgress`. |
| `sqs__queue-detail`, `-created`, `-purged`, `sqs__dlq-detail`, `sqs__dlq-redrive-*` | One sentence under the name, with counts of another queue in it (`which holds 1 now`, `exceeds 5`) and of the redrive task. | The server's sentence (`resources/says/sqs.rs`) reads this queue's own calls. | Built in the page, from reads of the other queue and of `ListMessageMoveTasks` (`sqs/sentences.ts`, `sqs/redrive-model.ts`, `sqs/queue-model.ts`); the server sentence is what shows until they have been read. |
| `sqs__queue-detail` | "Wired to" starts with the rule that feeds the queue (`payment-settled rule, bus larder`). | EventBridge lists the rules that target an ARN one bus at a time. | The page lists the buses and asks each bus (`ListEventBuses`, `ListRuleNamesByTarget`, bound to this queue in `resources/sqs.rs`) and puts the rules first, as `Fed by`. The same list is what the delete and purge confirms say about rules. |
| `sqs__queue-detail`, `-created` | `With a .doze name: http://sqs.us-east-1.aws.larder.doze/...` under the URL. | A doze-aws on its own has no `.doze` names; those come from the doze app that runs it. | The line is not drawn. The ARN and the URL are, each with a copy button. |
| `sqs__queue-detail`, `sqs__dlq-detail` | The verbs are `Edit Delete Purge Send and receive messages Start DLQ redrive` on a queue, and `Start DLQ redrive` alone on a dead-letter queue. | A redrive starts on a queue that is some queue's dead-letter queue; every queue can be edited, purged, sent to and deleted. | Every queue has Edit, Delete, Purge and Send and receive; `Start DLQ redrive` only on a dead-letter queue (`says/sqs.rs`). |
| `sqs__queue-messages-polled`, `-messages`, `sqs__message-detail` | `Poll for messages` receives with the queue's visibility timeout, so a polled message is hidden from the consumers for that long. | A poll is `ReceiveMessage` and counts as a receive; the console polls with a visibility timeout of 0, so it hides nothing (`resources/sqs.rs`, the `ReceiveMessage` op). | Built as the peek: the page says so under the button. The receive count still goes up, and the page names the messages near the dead-letter limit. |
| `sqs__queue-encryption`, `sqs__queue-detail`, `sqs__queues-list` | `Enabled with SSE-KMS` for a queue with a key. | `GetQueueAttributes` reports `SqsManagedSseEnabled` as `true` whether or not a KMS key is set (`crates/aws-sqs/src/attrs.rs`, `attributes`); AWS reports `false` with a key. | The page reads a `KmsMasterKeyId` as SSE-KMS and otherwise `SqsManagedSseEnabled` as SSE-SQS (`sqs/queue-model.ts`). The backend difference is left as it is: it is not a console decision. |
| `sqs__queue-create`, `-create-fifo` | Every field carries a hint from the neighbours (`pick-lists uses 30 seconds. pick-lists keeps 4 days; pick-lists-dlq keeps 14`). | The list reads a queue's name and counts, not its settings; a queue's settings are one `GetQueueAttributes` each. | The hints are those of the queue whose name is typed, when it exists (its detail is read): `pick-lists already exists in this Region`, its visibility timeout and retention. No other queue's settings are read. |
| `sqs__queue-create-refused` | `QueueNameExists: a queue named pick-lists already exists with a different value for VisibilityTimeout.` | The words are the service's: `A queue already exists with the same name and a different value for attribute VisibilityTimeout` (`crates/aws-sqs/src/queues.rs`). | The banner, the field and the call panel carry the service's words and code; the attribute is read out of them and the existing queue's value is shown beside the form. |
| `sqs__queue-sns-subscriptions`, `-sns-subscribe` | `The topic orders-created delivers to invoice-queue, inventory-queue and analytics-queue today` and `3 subscriptions, all SQS, with raw message delivery off`. | The topics list says how many subscriptions each topic has; naming the queues and reading each subscription's delivery attributes is a read per subscription. | The sentences say the counts (`delivers to 3 subscriptions today`, `already has 3 subscriptions`) and leave the names and the raw-delivery setting out. |
| `sqs__queues-list`, `sqs__queue-detail`, `sqs__message-detail`, `sqs__dlq-redrive-*` | Times as `Nov 6, 2026 18:42`. | The console writes every time as `2026-11-06 18:42:00 UTC` (`@doze/ui/lib/format`). | The console's own format, as on every page. |
| `sqs__queue-create-fifo`, `sqs__queue-edit` | `FIFO throughput limit`, the data key reuse period and encryption are `Stored, not applied locally`. | True: `FifoThroughputLimit` is validated and returned and nothing is throttled (`crates/aws-sqs/src/attrs.rs`); no message is encrypted, and no key policy is read. | Built as the board says; the words are the kit's `LocalStatus`. |
| `sns__topic-detail` | "Wired to" names the publisher that feeds the topic. | The strip is built from the resource's own links and lists (`resources/page.rs::wired`): what it points at, not what points at it. | Built in the page: the strip runs from the callers of `Publish` in the record of calls (as access keys), through the topic, to what its confirmed subscriptions deliver to (`sns/topic-parts.tsx`). |
| `sns__topic-create`, `sns__topic-edit`, `sns__topic-delivery-policy` | `Stored, not applied locally. Delivery here is synchronous, so there is no retry schedule to observe.`; `doze-aws does not retry`. | A failed `http` or `https` POST is tried again under the delivery policy (the subscription's own, else the topic's effective one: `retry_waits`, `crates/aws-sns/src/webhook.rs`); a `backoffFunction` other than linear is approximated by linear there. An SQS or Lambda delivery is one attempt. | The tab, the form and the table say the policy is applied to HTTP and HTTPS subscriptions (with the linear approximation) and that SQS and Lambda are one attempt. No `Stored, not applied` words on it. |
| `sns__subscription-create`, `-edit`, `-detail` | `Stored, not applied locally for payload-based filtering: a body-scoped policy is matched as if it were attribute-scoped.` | `FilterPolicyScope` `MessageBody` is applied: the policy is parsed for the scope it has and matched against the body (`crates/aws-sns/src/filter.rs`, `filter_at.rs`, `model.rs`). | Both scopes are offered with no local-status words. The publish page previews only a policy of attribute scope it can read (exact values, prefix, suffix, anything-but, exists, numeric); a body-scoped or more complex one says the service decides (`sns/filter-match.ts`). |
| `sns__subscription-create`, `-create-http`, `-create-lambda`, `-edit` | The redrive policy is `Stored, not applied locally`; nothing is sent to the queue. | A message SNS finally cannot deliver is sent to the dead-letter queue (`crates/aws-sns/src/dead_letter.rs`: on a client error at once for SQS and Lambda, after the retries for HTTP). | The section says it is applied by doze-aws, with when; the queue is chosen from those of the topic's type. |
| `sns__topic-create`, `-edit`, `sns__topic-logging` | `HTTP, AWS Lambda and Amazon SQS log locally. A success role writes one JSON record per successful delivery to a CloudWatch Logs group`. | Nothing writes a delivery log: the six feedback attributes are validated, kept and returned (`crates/aws-sns/src/topic_attrs.rs`); no code reads them on delivery. | Built as `Stored, not applied locally`: the roles and rates are recorded and returned, doze-aws writes no delivery logs. The topic sentence on the tab says the same. |
| `sns__topic-delete`, `sns__topic-deleted` | `the subscriptions are deleted asynchronously`; `The orders app now gets NotFound on every publish to orders-created`. | `DeleteTopic` removes the subscriptions in the same call (`crates/aws-sns/src/topics.rs`, `delete_topic`); nobody named `the orders app` is known to the console. | The dialog says the subscriptions are deleted with the topic, at once, and names them; the list says `A publish to orders-created now gets NotFound: the topic does not exist.` |
| `sns__topic-detail`, `-alerts`, `-access`, `-tags-none`, `-archive` and the other topic boards | A description under the name (`Order events from the orders app, fanned out to three SQS queues.`) and `Created Nov 6, 2026 19:02.` | An SNS topic has no description and no creation time (`GetTopicAttributes`). | Not drawn. A FIFO topic keeps the board's one line about order within a message group, which is the service's own definition. |
| `sns__topic-detail` | The header has Edit only. | Publish message and Delete are reached from the list on the board, and nowhere on the topic's own page. | The page also has Publish message and Delete in its header (the list keeps them too). |
| `sns__topic-detail`, `-alerts`, `-created`, `-published`, `sns__subscription-detail`, `sns__topics-list` | Results such as `200, delivered to 3`, `200, 3 subscriptions`, `200, pending confirmation`; publishers `orders (go)`, `notifications (ts)`. | The record of calls keeps the status, not a sentence of what the call did, and callers are access keys (`CallRecord`). | The calls tables show the status (`200`) and the caller as the record has it. The publisher in the strip is the access key of each caller of `Publish` in the record. |
| `sns__subscription-create`, `-edit`, `sns__topic-logging`, `sns__topic-create` | `Platform application endpoint` and `SMS` are `declined`. | A subscription of protocol `sms` or `application` is accepted and the messages sent nowhere (decision D1, `crates/aws-sns/src/lib.rs`, `deliver.rs`); `firehose` is kept and nothing is delivered to it. | The five protocols are disabled with the board's reasons, but the two say `accepted and sent nowhere` where the board says `declined`. |
| `sns__topic-create` | `The AWS managed key alias/aws/sns is selected by default.` | There is no `alias/aws/sns` unless KMS has made it; the form offers the aliases KMS lists. | Turning encryption on asks for a key, chosen from KMS's aliases or typed as an ARN, and says what is known of it (`symmetric and enabled`). |
| `sns__topic-create-refused`, `sns__publish-fifo-refused` | `InvalidParameter` and `If you don't provide a MessageDeduplicationId ... the action fails.` | The service answers `InvalidParameterException` with `Invalid parameter: Topic Name`, and for a missing ID `The topic should either have ContentBasedDeduplication enabled or MessageDeduplicationId provided explicitly` (`crates/aws-sns/src/message.rs`). | The banner and the call panel carry the service's code and words; the field says the board's rule (`the name must end with the .fifo suffix`, `Required: this topic does not have ContentBasedDeduplication set.`). The refused states keep the form's other sections instead of hiding them. |
| `sns__topics-list`, `sns__subscriptions-list` | `Previous` and `Next` page buttons. | `ListTopics` and `ListSubscriptions` pages go forward by a token only. | `Next` loads the next page when there is one; `Previous` is drawn off. |
| `sns__subscription-create-http` | `The answer is the string pending confirmation`. | With `ReturnSubscriptionArn: true`, which the console sends, the answer for a subscription that waits is its ARN (`crates/aws-sns/src/subs.rs`). | The page opens on the pending subscription, which says it waits (and that Edit works on it and Unsubscribe does not: SNS refuses to unsubscribe one that is pending). |
| `sns__topic-create`, `-edit`, `sns__publish-message`, `-fifo`, `sns__subscription-create`, `-edit` | The call panel shows a nested call (`Attributes`, `DisplayName = ...`). | SNS is a query-protocol service: the preview's `json` is the flat form (`Attributes.entry.1.key`). | The kit nests the dotted keys for display (`kit/wire-json.ts`); a list of structures is an array of them, a map's entries an object. |

## How a slice adds a row

Append a row in the table above, in the same commit as the code that departs from the board. Name the board exactly, quote what it
says, say what the backend does and where, and say the decision (built to the backend, or deferred with the owner's reason).
