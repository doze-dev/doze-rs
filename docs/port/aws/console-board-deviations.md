# Where the console does not do what a board says

The boards of the design canvas (`8fb38ec7-de4e-4570-b8c8-d1eabfe70929`) are the spec for the doze-aws console, with one exception:
a board that says something false of doze-aws, or asks for something doze-aws cannot do, is built to what the backend does. Each
such case is a row here, written by the slice that met it. The canvas is not edited.

A row says which board, what the board says, what the backend does (with the file that shows it), and what was decided.
| Board | What the board says | What the backend does | Decision |
| --- | --- | --- | --- |
| `sqs__queue-detail` | The sentence ends "which holds 1 now" (the dead-letter queue's own message count). | The detail makes the calls of the queue itself; the dead-letter queue's count is another queue's attributes, which no call of this page reads (`crates/aws-console/src/resources/says/sqs.rs`). | The sentence names the dead-letter queue and its maximum receives and leaves the count out. The queue's own page says its count. |
| `sqs__dlq-detail` | "…which sends a message here once its receive count exceeds 5" (the source queue's maximum receives). | The source queue's redrive policy is that queue's attribute, not read from the dead-letter queue's page. | The sentence says "It is the dead-letter queue of pick-lists." and leaves the number out. |
| `sqs__queue-detail`, `sns__topic-detail` | "Wired to" names the rule, publisher or key that feeds the resource (`payment-settled rule, bus larder`). | The strip is built from the resource's own links and lists (`resources/page.rs::wired`): what it points at, not what points at it. | Built to what the descriptor knows. Inbound wiring needs a read in the other services and is not built. |
| `s3__bucket-create`, `s3__ownership-edit` | Object Ownership: "Stored, not applied locally. ACLs are canned here, so no ownership setting changes who can read an object." | Ownership is applied: with Bucket owner enforced a request that grants more than the owner's full control is refused with AccessControlListNotSupported; with the other two, ACLs are kept and an AllUsers grant makes a bucket or object readable (`crates/aws-s3/src/acl.rs`). | The pages say so and carry no "stored" words for ownership. |
| `s3__bpa-edit`, `s3__bucket-create` | Only Block public policy is enforced; the other three Block Public Access settings are "stored, not applied locally". | All four act: BlockPublicAcls refuses a public ACL write, IgnorePublicAcls and RestrictPublicBuckets change what an anonymous request may read (`acl.rs`), BlockPublicPolicy refuses a public policy (`validate.rs`). | Built to what the crate does; no "stored" words. |
| `s3__lifecycle-create` | Size filters, "Number of newer versions to retain" and deleting expired delete markers are "Not available in doze-aws". | The janitor applies prefix, tag and size filters, `NewerNoncurrentVersions` and `ExpiredObjectDeleteMarker` (`crates/aws-s3/src/lifecycle.rs`). Only transitions are kept and never acted on (one storage tier). | Size, newer versions and delete markers are offered; transitions are left out, with the board's reason. |
| `s3__website-edit` | "Redirect requests for an object" is not available; the endpoint serves index and error documents only. | `RedirectAllRequestsTo` is served (a 301 for every request, `crates/aws-s3/src/website.rs`); routing rules are kept and not applied. | Redirect of every request is offered (host and protocol); routing rules are not, and the page says the local endpoint does not apply them. |
| `s3__upload` | Storage class "Not available"; the largest file the console can upload is 160 GB. | A storage class is kept on the object and listed (`put.rs`), with no effect; through the console an upload is at most 25 MiB (`api/deep.rs` UPLOAD_MAX). | The class is offered, marked stored, not applied locally; the page says 25 MiB and points to the CLI. The metadata editor has no Type column: a system header name is read as system defined, any other key as user defined. Add folder is a file chooser of a directory; dropping a folder is not read. |
| `s3__object-presign` | "Expiry is enforced here; the signature itself is not verified." | True under `--auth trust` (the default). Under `--auth verify` the console holds no issued key, so a link it signs is refused (`api/objects.rs`). | The dialog says which of the two this doze-aws is. |
| `s3__object-detail` | "Object URL" with a `.doze` name; the sentence names the writer (`written by catalog at 08:13:41`). | The console knows no `.doze` name for a bucket, and the Live record does not carry an object's key, so the writer of one object cannot be named. | The URL is the endpoint's path-style address; the sentence gives the last-modified time and the versions. |
| `s3__bucket-objects`, `s3__bucket-objects-versions` | Wired to `catalog (go) writes → product-images → resize-product-image`. | The strip is what the bucket points at (its notification destinations), not who writes to it (see `sqs__queue-detail`). The sentence leaves out "catalog wrote the last one a moment ago". | Built to what the descriptor knows. |
| `s3__buckets-list` | The line names which bucket has versioning and whom it notifies. | The list reads names, Regions and dates only; a bucket's versioning and notifications are on its own page. | The line is `N buckets in this account, all in us-east-1.` |
| `s3__object-copy` | Browse S3 browses buckets and folders. | Browse S3 chooses a bucket and a typed folder prefix; the destination field takes `s3://bucket/folder/` as the board does. Folders of another bucket are not listed (the kind's operations are CopyObject and CreateBucket only). | Partial, by choice of the whitelist. |

## How a slice adds a row

Append a row in the table above, in the same commit as the code that departs from the board. Name the board exactly, quote what it
says, say what the backend does and where, and say the decision (built to the backend, or deferred with the owner's reason).
