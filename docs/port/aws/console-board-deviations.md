# Where the console does not do what a board says

The boards of the design canvas (`8fb38ec7-de4e-4570-b8c8-d1eabfe70929`) are the spec for the doze-aws console, with one exception:
a board that says something false of doze-aws, or asks for something doze-aws cannot do, is built to what the backend does. Each
such case is a row here, written by the slice that met it. The canvas is not edited.

A row says which board, what the board says, what the backend does (with the file that shows it), and what was decided.
| Board | What the board says | What the backend does | Decision |
| --- | --- | --- | --- |
| `sqs__queue-delete`, `sqs__queue-deleted`, `sqs__queue-purge`, `sqs__queue-purged` | A delete and a purge are at once, and `--sqs-strict` is the flag that makes doze-aws refuse a re-create or a second purge for 60 seconds. | The wait is the default, as on AWS: `QueueDeletedRecently` and `PurgeQueueInProgress` are answered unless doze-aws starts with `--sqs-skip-60s-waits`; there is no `--sqs-strict` (`crates/aws-sqs/src/queues.rs`, `crates/doze-aws/src/keys.rs`). | The copy says what happens: AWS and doze-aws refuse for 60 seconds, and `--sqs-skip-60s-waits` lifts it. The e2e purges twice and sees `PurgeQueueInProgress`. |
| `sqs__queue-detail`, `-created`, `-purged`, `sqs__dlq-detail`, `sqs__dlq-redrive-*` | One sentence under the name, with counts of another queue in it (`which holds 1 now`, `exceeds 5`) and of the redrive task. | The server's sentence (`resources/says/sqs.rs`) reads this queue's own calls. | Built in the page, from reads of the other queue and of `ListMessageMoveTasks` (`sqs/sentences.ts`, `sqs/redrive-model.ts`, `sqs/queue-model.ts`); the server sentence is what shows until they have been read. |
| `sqs__queue-detail` | "Wired to" starts with the rule that feeds the queue (`payment-settled rule, bus larder`). | EventBridge lists the rules that target an ARN one bus at a time. | The page lists the buses and asks each bus (`ListEventBuses`, `ListRuleNamesByTarget`, bound to this queue in `resources/sqs.rs`) and puts the rules first, as `Fed by`. The same list is what the delete and purge confirms say about rules. |
| `sqs__queue-detail`, `-created` | `With a .doze name: http://sqs.us-east-1.aws.larder.doze/...` under the URL. | A doze-aws on its own has no `.doze` names; those come from the doze app that runs it. | The line is not drawn. The ARN and the URL are, each with a copy button. |
| `sqs__queue-detail`, `sqs__dlq-detail` | The verbs are `Edit Delete Purge Send and receive messages Start DLQ redrive` (greyed) on a queue, and `Start DLQ redrive` alone on a dead-letter queue, with no tabs. | A redrive starts on a queue that is some queue's dead-letter queue; every queue can be edited, purged, sent to and deleted, and a dead-letter queue is a queue like any other. | Every queue has Edit, Delete, Purge and Send and receive; `Start DLQ redrive` is always listed (`says/sqs.rs`) and the page greys it, with the reason on hover, on a queue that is no one's dead-letter queue. A dead-letter queue keeps its verbs and its tabs: the redrive status card is the first thing on its Dead-letter queue tab. |
| `sqs__queue-messages-polled`, `-messages`, `sqs__message-detail` | `Poll for messages` receives with the queue's visibility timeout, so a polled message is hidden from the consumers for that long. | A poll is `ReceiveMessage` and counts as a receive; the console polls with a visibility timeout of 0, so it hides nothing (`resources/sqs.rs`, the `ReceiveMessage` op). | Built as the peek: the page says so under the button. The receive count still goes up, and the page names the messages near the dead-letter limit. |
| `sqs__queue-encryption`, `sqs__queue-detail`, `sqs__queues-list` | `Enabled with SSE-KMS` for a queue with a key. | `GetQueueAttributes` reports `SqsManagedSseEnabled` as `true` whether or not a KMS key is set (`crates/aws-sqs/src/attrs.rs`, `attributes`); AWS reports `false` with a key. | The page reads a `KmsMasterKeyId` as SSE-KMS and otherwise `SqsManagedSseEnabled` as SSE-SQS (`sqs/queue-model.ts`). The backend difference is left as it is: it is not a console decision. |
| `sqs__queue-create`, `-create-fifo` | Every field carries a hint from the neighbours (`pick-lists uses 30 seconds. pick-lists keeps 4 days; pick-lists-dlq keeps 14`). | The list reads a queue's name and counts, not its settings; a queue's settings are one `GetQueueAttributes` each. | The hints are those of the queue whose name is typed, when it exists (its detail is read): `pick-lists already exists in this Region`, its visibility timeout and retention. No other queue's settings are read. |
| `sqs__queue-create-refused` | `QueueNameExists: a queue named pick-lists already exists with a different value for VisibilityTimeout.` | The words are the service's: `A queue already exists with the same name and a different value for attribute VisibilityTimeout` (`crates/aws-sqs/src/queues.rs`). | The banner, the field and the call panel carry the service's words and code; the attribute is read out of them and the existing queue's value is shown beside the form. |
| `sqs__queue-sns-subscribe` | `3 subscriptions, all SQS, with raw message delivery off`. | Reading each subscription's delivery attributes is a read per subscription. | The topic's name and its ARN are said; the raw-delivery setting is left out. (`sqs__queue-sns-subscriptions` now names the queues the topic delivers to, from the topic's own subscriptions, by name: the subscriptions come in no order worth keeping.) |
| `sqs__queues-list`, `sqs__queue-detail`, `sqs__message-detail`, `sqs__dlq-redrive-*` | Times as `Nov 6, 2026 18:42`. | The console writes every time as `2026-11-06 18:42:00 UTC` (`@doze/ui/lib/format`). | The console's own format, as on every page. |
| `sqs__queue-create-fifo`, `sqs__queue-edit` | `FIFO throughput limit`, the data key reuse period and encryption are `Stored, not applied locally`. | True: `FifoThroughputLimit` is validated and returned and nothing is throttled (`crates/aws-sqs/src/attrs.rs`); no message is encrypted, and no key policy is read. | Built as the board says; the words are the kit's `LocalStatus`. |
| `sqs__queue-detail`, `sqs__dlq-detail`, `sqs__dlq-redrive-*` (Recent calls) | The result column says what came back (`200 53 bytes`, `200 2 messages`, `200 no tasks`), and the caller is an app (`fulfilment (py)`). | A call record holds the status, the error, how long the call took, the access key, the client's User-Agent and, for a call between services, who made it and for what (`crates/aws-console/src/model.rs`, `CallRecord`); it does not hold the answer's body. | The caller is the IAM user's name, `EventBridge rule payment-settled` for a call a service made, else the client (`AWS CLI`) with the key beside it; the result is the status and how long the call took (`kit/calls.ts`, `kit/recent-calls.tsx`). Sizes and counts of answers wait for the recorder to keep a summary of them. |
| `sqs__message-detail` | `Returned by ReceiveMessage` has no `MD5OfBody` and cuts the receipt handle (`AQEB...`). | The JSON is the service's answer for that message. | Built as the answer is: the whole receipt handle and `MD5OfBody`. The details open in a dialog with Close only; a message is deleted from the table, where it is chosen. |
| `sqs__queue-messages-fifo` | The send form has no message attributes. | A FIFO queue takes message attributes as a standard one does. | The attributes stay on the FIFO form. |
| `sqs__queue-create-fifo` | `Deduplication scope` and `FIFO throughput limit` are greyed until `Enable high throughput FIFO` is on. | The two are attributes of their own: `DeduplicationScope` is applied (`crates/aws-sqs/src/fifo.rs`) and each can be set without the other. | The selects stay live; the checkbox sets both, and changing either alone turns it off, as the board's own line says. `Stored, not applied locally` sits under the throughput limit only. |
| `sqs__queues-list` | `1 to 7 of 7 queues` with previous and next arrows. | `ListQueues` pages forward with a token; there is no previous page to ask for. | The line and `Load more` while the service has more. |
| `sqs__queue-messages-polled`, `sqs__message-deleted` | The Send card is not on the page after a poll. | Sending is still what the person may want next. | A poll folds the Send card to its title with `Show the form`. |
| `sns__topic-detail` | "Wired to" names the publisher that feeds the topic. | The strip is built from the resource's own links and lists (`resources/page.rs::wired`): what it points at, not what points at it. | Built to what the descriptor knows; the SNS slice decides on inbound wiring (the SQS queue page reads its feeders with bound operations, `sqs/feeders.ts`). |
| `s3__bucket-create`, `s3__ownership-edit` | Object Ownership: "Stored, not applied locally. ACLs are canned here, so no ownership setting changes who can read an object." | Ownership is applied: with Bucket owner enforced a request that grants more than the owner's full control is refused with AccessControlListNotSupported; with the other two, ACLs are kept and an AllUsers grant makes a bucket or object readable (`crates/aws-s3/src/acl.rs`). | The pages say so and carry no "stored" words for ownership. |
| `s3__bpa-edit`, `s3__bucket-create` | Only Block public policy is enforced; the other three Block Public Access settings are "stored, not applied locally". | All four act: BlockPublicAcls refuses a public ACL write, IgnorePublicAcls and RestrictPublicBuckets change what an anonymous request may read (`acl.rs`), BlockPublicPolicy refuses a public policy (`validate.rs`). | Built to what the crate does; no "stored" words. |
| `s3__lifecycle-create` | Size filters, "Number of newer versions to retain" and deleting expired delete markers are "Not available in doze-aws". | The janitor applies prefix, tag and size filters, `NewerNoncurrentVersions` and `ExpiredObjectDeleteMarker` (`crates/aws-s3/src/lifecycle.rs`). Only transitions are kept and never acted on (one storage tier). | Size, newer versions and delete markers are offered; transitions are left out, with the board's reason. |
| `s3__website-edit` | "Redirect requests for an object" is not available; the endpoint serves index and error documents only. | `RedirectAllRequestsTo` is served (a 301 for every request, `crates/aws-s3/src/website.rs`); routing rules are kept and not applied. | Redirect of every request is offered (host and protocol); routing rules are not, and the page says the local endpoint does not apply them. |
| `s3__upload` | Storage class "Not available"; the largest file the console can upload is 160 GB. | A storage class is kept on the object and listed (`put.rs`), with no effect; through the console an upload is at most 25 MiB (`api/deep.rs` UPLOAD_MAX). | The class is offered, marked stored, not applied locally; the page says 25 MiB and points to the CLI. The metadata editor has no Type column: a system header name is read as system defined, any other key as user defined. Add folder is a file chooser of a directory; dropping a folder is not read. |
| `s3__object-presign` | "Expiry is enforced here; the signature itself is not verified." | True under `--auth trust` (the default). Under `--auth verify` the console holds no issued key, so a link it signs is refused (`api/objects.rs`). | The dialog says which of the two this doze-aws is. |
| `s3__object-detail` | "Object URL" with a `.doze` name; the sentence names the writer (`written by catalog at 08:13:41`). | The console knows no `.doze` name for a bucket, and the Live record does not carry an object's key, so the writer of one object cannot be named. | The URL is the endpoint's path-style address; the sentence gives the last-modified time and the versions. |
| `s3__bucket-objects`, `s3__bucket-objects-versions` | Wired to `catalog (go) writes → product-images → resize-product-image`. | The strip is what the bucket points at (its notification destinations), not who writes to it (see `sqs__queue-detail`). The sentence leaves out "catalog wrote the last one a moment ago". | Built to what the descriptor knows. |
| `s3__buckets-list` | The line names which bucket has versioning and whom it notifies. | The list reads names, Regions and dates only; a bucket's versioning and notifications are on its own page. | The line is `N buckets in this account, all in us-east-1.` |
| `s3__object-copy` | Browse S3 browses buckets and folders. | Browse S3 chooses a bucket and a typed folder prefix; the destination field takes `s3://bucket/folder/` as the board does. Folders of another bucket are not listed (the kind's operations are CopyObject and CreateBucket only). | Partial, by choice of the whitelist. |
| `lambda__function-config`, `lambda__config-edit`, `lambda__function-create` | The execution role is "Stored, not applied locally: nothing enforces the role". | The role is applied: a function's process gets an STS session for it, so under `--iam enforce` it has the role's permissions and no others, and under `soft` a call the role does not allow is logged (`crates/aws-lambda/src/role.rs`). Memory and ephemeral storage are stored, with no limit applied. | The pages say the role is applied; "Stored, not applied locally" stays on memory and ephemeral storage only. |
| `lambda__trigger-add`, `lambda__trigger-edit` | Batch window, partial batch responses, maximum concurrency and filter criteria are "not available in doze-aws": they "would be discarded". | All four act on an SQS mapping: the batch window (`poll/sqs.rs`), `ReportBatchItemFailures` (`poll/mod.rs`), `ScalingConfig.MaximumConcurrency` (`poll/sqs.rs`) and the filter (`poll/filter.rs`). Provisioned pollers are only stored. | The Add trigger form has the four as fields of its collapsed section; Provisioned Mode stays "not available". Edit trigger changes the enabled state and batch size only and says the rest is kept as it is. |
| `lambda__alias-create` | Weighted alias: "routing weights are accepted and not kept, so an alias always runs the one version it names". | The weights are kept and used: an invocation of the alias is routed between its version and the additional one by them (`crates/aws-lambda/src/aliases.rs`). | Built: a collapsed Weighted alias section (an additional version and its percentage, sent as `RoutingConfig.AdditionalVersionWeights`). |
| `lambda__function-monitor` | doze-aws publishes four metrics (Invocations, Duration, Errors, Throttles); ConcurrentExecutions is not published. | `AWS/Lambda` has Invocations, Errors, Duration and ConcurrentExecutions for every function, and Throttles once a call has been throttled (`crates/aws-lambda/src/metrics.rs`). | The tiles are the four of the board (Throttles reads 0 until one is throttled); the note names ConcurrentExecutions. Read with CloudWatch's `GetMetricData` through the metrics kind's operation. |
| `lambda__test-result-throttled` | The message is "function send-email is throttled (reserved concurrency 0)". | The service answers `TooManyRequestsException` with its own words (HTTP 429). | The page shows the service's code, status and message in Error details, and the reason ("reserved concurrency 0") from the function's own `Concurrency.ReservedConcurrentExecutions`. |
| `lambda__function-url`, `lambda__url-create`, `lambda__function-url-created` | The URL is `https://<id>.lambda-url.<region>.on.aws/`; "Also at" is `<endpoint>/_aws/lambda-url/<id>/`. | The URL doze-aws gives is `http://<id>.lambda-url.<region>.localhost:<port>/`, and the path form carries the Region: `<endpoint>/_aws/lambda-url/<region>/<id>/` (`crates/aws-lambda/src/web.rs`). | The page shows what the service returned and the path form with the Region. |
| `lambda__destination-add` | The call is `UpdateFunctionEventInvokeConfig`. | Update refuses a function that has no asynchronous configuration yet (`ResourceNotFoundException`, `crates/aws-lambda/src/settings.rs`); Put makes the first. | The page reads `GetFunctionEventInvokeConfig`: Update when there is one, Put (said under the call) when there is not. |
| `lambda__function-versions` | $LATEST's description is "The unpublished version"; the versions are listed newest first after $LATEST. | `ListVersionsByFunction` returns the function's own description for $LATEST, and versions in ascending order. | The table is sorted as the board's (newest first, $LATEST on top) and shows the description the service returned. |
| `lambda__function-code` | A code editor with Deploy, and an Explorer. | The package is a zip: the console reads it through `GET …/lambda/functions/<name>/code` (Lambda's own download, no network) and the page reads and writes the archive (`lambda/zip.ts`); Deploy sends the changed archive with `UpdateFunctionCode`. | Built: the handler's file opens; other text files up to 400 KB can be chosen in the Explorer; binary and larger files are listed, greyed, and sent back as they were. An image function has no code to show. |
| `lambda__functions-list` | The sentence names runs in the last hour and "export-report once, at 02:00 by its schedule". | The counts are CloudWatch's `AWS/Lambda` `Invocations` for the hour; no list call says what a schedule did. | The sentence says `N functions run here.` and the invocations of the last hour, most first, without the schedule clause. |
| `lambda__layers-list`, `lambda__functions-list` | `1 to 1 of 1 layers`. | The shared paging line says the noun in the singular for one. | `1 to 1 of 1 layer`. |
| `lambda__function-created`, `lambda__function-deleted`, `lambda__env-none`, `lambda__triggers-none`, `lambda__permissions-none`, `lambda__aliases-none` | The header of these boards has no sentence, no "Triggered by" strip and no layers or recent calls (and, for the "none" boards, a `python3.13` badge in place of Zip and Active). | The page is one page for every function. | The sentence and badges are always there; the Triggered by strip is drawn only when something triggers the function; Recent calls follow every tab. |
