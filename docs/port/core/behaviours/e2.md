## Where Rust differs from Go, on purpose

| # | Go | Rust | Why |
|---|---|---|---|
| E1 | A partial line grows without a bound | a line is cut at 64 KiB | a process that never prints a newline must not grow doze |
| E2 | A pipe's last line without a newline waits for the run's close | it is recorded when that pipe closes | a step's last words reach the log as it ends |
| E3 | Reopening after a torn last line appends to it, so the next event is lost too | the torn line is ended with a newline first | the next event reads back |
| E4 | `Subscribe` drops events silently past its buffer | a lagging subscriber is told how many it missed (`Lagged`) | it knows to fill the gap with `since` |
| E5 | The sync lock is a file made with `O_EXCL`, broken after 2 minutes | the system's file lock (released however the holder ends) | no stale lock to break, no two syncs after a break. A Go doze sees Rust's lock file and waits its 2 minutes |
| E6 | Pipes for every process | the same, with the trees killed whole and a pump still held open after a stop dropped after 1 s; the process that held it (it left its group) then dies of SIGPIPE at its next write | W0: a server a tool left behind must not keep a pump alive (`tests/pumps.rs an_escaped_holder_of_the_pipe_neither_hangs_a_stop_nor_writes_after_it`) |
| E7 | A failed hook quotes its whole output | the last 16 KiB of it | an error message is not a log; the log has it all |
| E9 | A task's record stays while it runs again; a run cut short keeps the old one (`done`, perhaps) | the record is dropped when a run starts: a run cut short (a stop, the daemon killed) leaves none, and the task runs again | a migration stopped half way must not count as done (`tests/tasks.rs a_stopped_task_leaves_no_record`) |
| E10 | A task's run line is `sh -c`; `ran_at` is local time with its offset | argument words (D14); `ran_at` in UTC | no shell (PLAN.md D14); either side reads either time |
| E11 | Where the system cannot list listening ports (no lsof or ss: Windows), the hint says the app "listens on no port" | no hint | a guess is worse than nothing |
| E8 | A failed start quotes the run after `stopAll` | the same order (E2 audit 1, M1) | the quote must have the last words (`tests/pumps.rs a_failed_start_quotes_its_last_words_without_a_newline`) |

Open from E2 audit 1, for a later pass: `is_stamp` checks the digit pattern, not the ranges `time.Parse` checks (m4); non-UTF-8 file names are skipped by `inputs` (m5); one write per line and pruning under the run's lock (m8); `follow` reads files inside an async fn, bounded at 512 lines (m9, D1 wires it); a closed run silently drops writes (m6: `rerun_on_ready` after a crash).

## Not yet in E2 (next session)

Wiring the real fetch service (F1's `ChildDownloads`) and `doze.lock`'s pins into the pool is the daemon's (D1): the engine takes any `Downloads` and the pins as values, so it does not link doze-fetch. A module's own restart policy, network grants and converge on a fresh provision come with D2's listeners.

## Weight

The engine now links `doze-journal` (serde, serde_json, `time`) and `doze-logstore` (tokio `sync` only). serde_json and
tokio were already in the weight probe; `time` (formatting and parsing) is the new one. No binary links the engine yet,
so the size is measured when `doze` does (weight.md).
