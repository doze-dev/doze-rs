# P1: `doze-os`, the platform crate

Status: P1a done 2026-11-12 (green on all five CI targets; on the elevated Windows x64 runner postgres started as a tree after the re-launch, ready in 568 ms, graceful stop). P1b in progress. Plan: `PLAN.md` D10, D11, D15; evidence: `spikes/s0-module-proto/REPORT.md`,
`spikes/w0-windows/REPORT.md`.

`doze-os` is the only crate in the workspace with `#[cfg(unix)]` / `#[cfg(windows)]` and the only one allowed
`unsafe` (owner, 2026-11-12). Every `unsafe` block is small, sits in a platform file, carries a `// SAFETY:` line
(`clippy::undocumented_unsafe_blocks` is denied) and is wrapped in a safe function. The crate cannot use
`[lints] workspace = true` (a forbidden lint cannot be relaxed per crate), so it repeats the workspace table with
`unsafe_code = "deny"`; keep the two in step.

## What it provides (P1a, this slice)

| module | what | Unix | Windows |
|---|---|---|---|
| `channel` | the module control channel, split into a reader and a writer; handing a client connection (`Passable`) to the other side with a frame | socketpair as the module's stdin; module dups it and points fd 0 at /dev/null; SCM_RIGHTS on the same socket | single-instance named pipe with an unguessable name, client pid verified; `WSADuplicateSocketW` bytes ride in the frame (`TRAILER`) |
| `group` | a set of processes that dies with the host, and per-process stop (`Stop`, D15) with escalation to a hard kill | process group per child; Linux: `PR_SET_PDEATHSIG`; macOS: none (core reconciles pidfiles at start) | a kill-on-close Job object; `CREATE_NEW_PROCESS_GROUP` so CTRL_BREAK reaches only that child |
| `privilege` | is this process privileged; on Windows, re-launch this process with the Administrators group disabled (what `pg_ctl` does) | euid 0 is privileged; no re-launch (doze refuses to run as root, as initdb does) | `CheckTokenMembership(Administrators)`; `CreateRestrictedToken` + `CreateProcessAsUserW` with the same command line, stdio inherited, exit code passed through |
| `which` | find an executable on `PATH` | executable bit | `PATHEXT` (`.cmd` and `.bat` run through std's batch handling) |

P1b: `fs` (exclusive locks via std `File::lock`, released by the OS however the holder dies; owner-only
directories: 0700, or a protected DACL of the user and SYSTEM; data-dir clone: `cp -c` / `cp --reflink=auto` / a plain
copy), `home` (`DOZE_HOME`, else `~/.doze`, `%LOCALAPPDATA%\doze`), `detach` (Unix `setsid`; Windows
`CREATE_NO_WINDOW | CREATE_NEW_PROCESS_GROUP`, breaking away from the starter's job when allowed). Windows security
helpers shared by `privilege` and `fs` live in `winsec.rs`.

- **A detached Windows daemon needs a console** to send CTRL_BREAK to its engines: `CREATE_NO_WINDOW` gives it a hidden
  one; `DETACHED_PROCESS` gives none, and every graceful stop would become a kill. `tests/detach.rs` proves the stop.

## Gotchas found on the way (keep)

- A restricted token keeps the elevated token's default owner and DACL (Administrators). With that group deny-only the
  process cannot open pipes or jobs it creates ("Access is denied", os error 5). Fix: owner = user, default DACL =
  user + SYSTEM (`privilege/dacl.rs`, what pg_ctl's AddUserToTokenDacl does). The token handle needs
  TOKEN_ADJUST_DEFAULT, inherited from the original handle's access.

- `PR_SET_PDEATHSIG` fires when the **thread** that spawned the child exits, not the process. Spawn engines from a
  long-lived thread (the runtime's main thread), never from `spawn_blocking`, whose threads exit when idle.
- A Job object assigned right after spawn leaves a microsecond window in which a child could start a grandchild
  outside it. Acceptable for engines (they spawn workers after start-up); the daemon also puts itself in a
  kill-on-close job, so nothing outlives it either way.
- `TokenElevation` still reports "elevated" for a restricted token derived from an elevated one; what engines check
  is membership of the enabled Administrators group, so that is what `is_privileged` checks.
- Capturing the output of a tool that leaves a server behind (`pg_ctl start`) never ends: the server inherits the
  pipes. Such tools run with null stdio (W0).
