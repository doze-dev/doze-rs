Generated by `tools/ux/pages-audit.ts` over the fixtures server, real Chrome, a real mouse click on each control with the control in the middle of the window.
**101 controls: 98 in place, 3 navigation, 0 main swap, 0 reload, 0 jump.**

- *in place*: no navigation, `main` not swapped, scroll kept, nothing above the data moved (what every same-page control must be).
- *navigation*: a crumb, a tab or a step of a form: a move to another page, which swaps `main` in a view transition and starts at the top of the new page (what it must be).
- *main swap*: a same-page control that swapped `main` (a cross-fade and a jump to the top): a defect.
- *reload*: a full document load. *JUMP*: the scroll was lost or something above moved.

## Before and after

The first audit (the page agent, before the foundation was merged) found **71 controls: 12 in place, 57 reload, 2 jump**. After the foundation merged (boosted navigation) the same controls were no longer reloads but **page swaps**: each cross-faded `main` and jumped to the top (`main swap`; 80 of the 100 controls the audit then counted). This pass makes each of them an in-place update of its own region. Now (the table above, the fixtures server, Chrome 152, 1280 by 800, each control clicked with a real mouse event):

| | before the foundation | foundation merged | after this pass |
|---|---|---|---|
| in place | 12 | 20 | **98** |
| main swap (cross-fade, jump to the top) | n/a | 80 | **0** |
| full reload | 57 | 0 | **0** |
| JUMP | 2 | 0 | **0** |
| navigation (a crumb, a tab, a form step: right) | not told apart | not told apart | 3 (of 101) |

Layout shift is 0 in every row; `scrollY` is unchanged in every in-place row; nothing above the data moved in any.

| Page | Region (id) | Holds | Controls that change it | Address |
|---|---|---|---|---|
| `/topics` | `topics-view` | sentence, toolbar, table or the no-match card, the internal note | filter box (as you type), Show internal, Refresh, Clear filter | `?q=&internal=`, typing replaces |
| `/groups` | `groups-view` | toolbar (the state Segmented control with its counts), table | filter box, the four states | `?q=&state=` |

| `/topics/{t}/config` | `config-view` | toolbar, explainer, sections | filter box, the four chips | `?q=&show=` |
| `/groups/{g}/lag` | `group-lag-view` | header, tabs, window, table, explanation | When do these expire? | `?expiring=1` |
| `/jump` | `jump-view` | filter and names | filter box | `?q=` |
| `/live` | `live-wire` (the foundation's) | the whole tape | filters, toggles, Pause, pagers | the query |

A region the answer does not have (an offline or empty topic reached by Clear filters) is covered two ways: those states carry the region, and the script follows the address if a region is missing (CON-752).

Not regions (a move to another page, right as it is): crumbs, the tabs of a topic or a group, the rail, a row's link, "Next: configuration" (a step of the create form), and everything that opens an overlay (the drawer and dialogs keep their own history entry).
