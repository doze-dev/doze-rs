# The component library: Select, Combobox, MultiSelect, DropdownMenu, Tooltip, Popover, Segmented control

shadcn/ui look on the kit's tokens: 1 px `--line2` border, radius 8, a soft shadow on popups, 14 px text, a check mark for the chosen item, muted descriptions, the accent focus ring. Each is a maud function in `src/ui/components/` that renders **complete, working markup with no script** and carries the `x-data` of an Alpine component in `assets/components.js` (the CSP build: method names only). When Alpine starts the component adds `is-on` to its root, which hides the plain control and shows the enhanced one; the plain control stays in the form and keeps the value, so a form submits the same either way. Gallery: `/gallery` (the examples build only: `cargo run -p kafka-console --features examples --example boards`). Tests: `src/ui/components/tests.rs` (markup, a11y roles and ids, hostile labels), `tools/dom/components.test.ts` (behaviour), `tools/ux/scenarios/components.ts` (real Chrome).

Every label, value and description is **text**: maud escapes it and the script copies it with `textContent`. A label such as `<img src=x onerror=alert(1)> "q" & 'q'` shows as that text in the plain control, the list, the trigger and the tooltip (`hostile_labels_values_and_descriptions_are_text_everywhere`).

A value is matched by its whole name (`WireQuery::topic_ok`), several of a kind are an OR and the kinds an AND (CON-852).

## In-place controls (not components, the pattern)

`ui::client::in_place_link(region_id, class, href, content)` and `in_place_form(region_id, class, action, content)` give a plain link or GET form the attributes that make it change only `#region_id` of its own page (scroll, focus and typed text stay, the address is pushed, only what changed fades). A page declares the region by giving the element an id (a `div.frag#id`); `region_id` is a literal of the page, never data.

## Adding one

A maud function with a `…Spec` struct, the `x-data="dzName"` and the stand-in names for the dotted Alpine attributes (`xo-click` for `x-on:click.outside`, `xa-bottom-start-4` for `x-anchor.bottom-start.offset.4`, `xb-aria-expanded` for `:aria-expanded`; maud cannot spell them, `components::alpine` puts the real ones back), the CSS in `design/console.css` (`.dz-…`; regenerate `assets/console.css` with `DOZE_UPDATE_DESIGN=1 cargo test -p kafka-console --lib assets`), a `A.data('dzName', …)` in `assets/components.js` (state in a closure, behaviour as named methods, the options are the server's elements and are never built from strings), a row above, markup tests, DOM tests, a gallery entry and a scenario.

## Where each is used (the integration pass)

| Component | Where | Why there |
|---|---|---|
| Segmented control | the partitions of a topic's Messages (up to 8, with "More" beside them), "Reading as" | a few mutually exclusive choices, one Tab stop, arrows; each is a link, so a choice is an address |
| MultiSelect | the Live apps, topics and APIs; the Groups states (with their counts); the partitions of a Messages topic ("More", or alone past 8) | a filter that takes several values, each with the rows it would leave |
| Select | a single choice from a short list (a dialog's field, the gallery) | a list that opens; a real `<select>` with no script |
| Combobox | a single choice from a list that grows (the gallery; a free-text field with suggestions) | a list that grows must be searchable |
| Popover | Messages "From time (UTC)": a field, what to write, Apply | the field is part of the toolbar's form, so Enter or Apply asks for the time and every other control carries it |
| DropdownMenu | the actions of a topic's own config value (Edit, Reset to the inherited value); a value that is not on the topic has one action and keeps its button | two or more actions in a row |
| Tooltip | the Tooltip component for a trigger that carries its own; **one shared card for every `title` and every text-less button's `aria-label`** (`components.js`, last block) | no id per use, the `title` is the no-script fallback |

## In-place helpers (`ui/inplace.rs`)

`region(id, content)` a wrapper that is the region; `link`, `link_with(.., Opts{label, ui, op}, ..)`, `chip_link` (a chip of a group, `aria-current`), `form(target, id, class, style, action, content)` (a toolbar, submit buttons inside are the controls), `search_box` and `search_input(&Search{..})` (the filter field: 250 ms after the last key, replaces the history entry, a newer request replaces the older, the rest of the form travels with it). The handler calls `region::canonical(<clean address>)`; the layer puts it in the history (CON-751). A `#anchor` stays in a link and is left out of the request.

## Cards stay clear of the rail

`components.js` (the block "Keep every floating card inside the page") nudges a shown `.dz-pop` sideways by a margin so it sits right of the rail and inside the window; it runs when the anchor rewrites the card's `style` and converges in one pass. Vertical placement is Floating UI's flip: a vertical nudge moved a card under the pointer mid-click (found by `select-mouse-and-outside`) and was dropped.
