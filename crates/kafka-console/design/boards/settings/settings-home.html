A transaction past its timeout is aborted by a check every 500 ms, and its producer is fenced. That check has no flag, and the timeout belongs to each producer (orders-eos: 60 s). A running broker cannot change these: Kafka refuses with "Cannot update these configs dynamically", and so does this one. To change an interval, stop the broker and start it with the flag.

What a restart does

SIGTERM or Ctrl-C is a clean stop: every open partition is flushed and closed and the stop is recorded, while a kill is not, and the next start distrusts every partition and the first flush covers what it reads back (nothing acknowledged is lost). Your data is where it was, including topics, records, configs, committed offsets, producer ids and open transactions (orders-eos stays Ongoing and its 60 s timeout is not started again), while connections, group members, the wire's 2,000 rows and Lab rules start again from nothing. Stored ACLs and the users made over the API stay; users from flags are re-applied.

A write that asked for acks=all is flushed before it is answered; one with acks=1 within 500 ms, set by --fsync-interval.
