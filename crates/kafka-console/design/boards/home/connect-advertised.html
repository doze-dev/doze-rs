Advertised listener

The trap: a client reaches the broker, is told another address, and cannot reach that one. This check does the same two steps a client does, from the broker's side.

This instance

Reachable

Advertised host and port equal the listener, so a client that reached it once can always reach it again.

What your client sees in the bad case

[[g:warn 18]]
The first request works, which is why this is confusing. Then the client logs a failure to connect to broker.internal:9092 and every produce and fetch times out. Nothing is wrong with the address you typed.

The call behind the check

One request, the same one every client sends first.

Metadata v12
  topics: []

→ brokers: [{ host: "127.0.0.1", port: 9092 }]
  then dial 127.0.0.1:9092 and send ApiVersions

What to set

One broker, one address: set the advertised host to a name or IP the client can reach, and the port it can reach it on.

doze-kafka --listen 0.0.0.0:9092 \
  --advertised-host 192.168.1.20 \
  --advertised-port 9092
From a container, 127.0.0.1 is the container. This check runs on the broker's side and cannot see inside your container's network: if clients there fail while this says Reachable, set a host name that the container resolves.
