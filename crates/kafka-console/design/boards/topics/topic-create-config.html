What the topic does with old records. Kafka's own sentence, the default and when it takes effect sit under each field.

[[g:check 12]]Name and partitions2Configuration3Review and create
cleanup.policy
delete
old segments go when they pass the retention time or size
compact
keep the latest record for every key; a record with no key is refused
delete,compact
both: compact what is kept, and drop what is too old
Kafka says the "delete" policy (the default) will discard old segments when their retention time or size limit has been reached. The "compact" policy retains the latest value for each key.
Default delete.
Range delete, compact, or both.
Takes effect read for each request; the cleaner looks every 15 s, retention every 5 m.
Here only compact makes keyless records refused (INVALID_RECORD).
= 7 d
Kafka says the maximum time we will retain a log before we discard old log segments, when using the "delete" policy. If set to -1, no time limit is applied.
Default 604800000 (7 d).
Range -1, or 0 and up.
Takes effect at the next retention pass (--log-retention-check-interval, 5 m); the active segment is never deleted.
Here clickstream sets 3600000 (1 h) and so deletes the most.

[[g:api 14]]The call
CreateTopics v7
  topics[0]
    name: orders.retry
    num_partitions: 3
    replication_factor: 1
    configs:
      cleanup.policy = delete
      retention.ms = 604800000
  validate_only: false
[[g:code 14]]Or from a terminal
# the same, with Kafka's own tool
kafka-topics.sh --bootstrap-server 127.0.0.1:9092 \
  --create --topic orders.retry --partitions 3 \
  --config cleanup.policy=delete \
  --config retention.ms=604800000
